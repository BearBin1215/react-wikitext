# Template expansion

The default pipeline does not execute templates. Use the `/expand` compiler to expand supported templates and parser functions before parsing. The library never performs network requests; template sources come from the host. Offline content, bundled sources or preloaded template sets can use the template table provider; on-demand sources implement a custom provider.

## Basic usage

```tsx
import { createTemplateTableProvider, createWikitextCompiler } from "react-wikitext/expand";
import { prepareWikitext } from "react-wikitext/hast";
import { WikitextView } from "react-wikitext/view";
import "react-wikitext/styles.css";

const provider = createTemplateTableProvider({
  key: "offline:example",
  revision: "templates-v1",
  templates: {
    "Template:Note": "'''{{{1|default note}}}'''",
    "Template:Empty": "",
  },
});

const compiler = createWikitextCompiler({ parser, provider });

const compilation = await compiler.compile(
  { key: "page:example", revision: "edit-1", text: "{{Note|offline}}{{Empty}}" },
  { pageName: "Example" },
);

const prepared = prepareWikitext(compilation.snapshot);
const view = <WikitextView snapshot={prepared} lang="en" />;
```

The preview below compares the default pipeline with the expanded result: the left side shows template placeholders, the right side the same source expanded by the compiler and prepared again.

```tsx preview
import { useEffect, useMemo, useState } from "react";
import { createTemplateTableProvider, createWikitextCompiler } from "react-wikitext/expand";
import { prepareWikitext, type WikitextRenderSnapshot } from "react-wikitext/hast";
import { createWikiparser, parseWikitext } from "react-wikitext/parse";
import { WikitextView } from "react-wikitext/view";
import "react-wikitext/styles.css";

const source = `'''Expansion''' replaces template calls with their source and parses the result again.

{{Note|argument}}

{{List}}

{{#if:1|true branch|false branch}}`;

const provider = createTemplateTableProvider({
  key: "demo",
  revision: "v1",
  templates: {
    "Template:Note": "'''Note:''' {{{1|missing}}}",
    "Template:List": "* first\n* second",
  },
});

const before = prepareWikitext(parseWikitext(source, { pageName: "Demo" }));
const pane = { flex: 1, minWidth: 0 };
const label = { margin: "0 0 8px", fontSize: 13, color: "#57606a" };

export default function Demo() {
  const compiler = useMemo(
    () => createWikitextCompiler({ parser: createWikiparser(), provider }),
    [],
  );
  const [after, setAfter] = useState<WikitextRenderSnapshot | null>(null);
  const [status, setStatus] = useState("");
  const [error, setError] = useState("");

  useEffect(() => {
    const controller = new AbortController();
    compiler
      .compile(
        { key: "demo", revision: "1", text: source },
        { pageName: "Demo", signal: controller.signal },
      )
      .then((compilation) => {
        if (!controller.signal.aborted) {
          setAfter(prepareWikitext(compilation.snapshot));
          setStatus(
            `status ${compilation.status}, ${compilation.snapshot.graph.invocations.length} invocations`,
          );
        }
      })
      .catch((reason) => {
        if (!controller.signal.aborted) {
          setError(reason instanceof Error ? reason.message : String(reason));
        }
      });
    return () => controller.abort();
  }, [compiler]);

  return (
    <div style={{ display: "flex", flexWrap: "wrap", gap: 16, alignItems: "flex-start" }}>
      <section style={pane}>
        <p style={label}>Default pipeline: placeholders</p>
        <WikitextView snapshot={before} lang="en" />
      </section>
      <section style={pane}>
        <p style={label}>{error ? error : after ? `Expanded: ${status}` : "Expanding…"}</p>
        {after ? <WikitextView snapshot={after} lang="en" /> : null}
      </section>
    </div>
  );
}
```

`compiler.compile`:

1. Normalizes newlines and registers `input` / `normalized` text sources.
2. Compiles only the page call structure and evaluates templates and functions in deterministic rounds.
3. Fetches uncompiled templates in batches, compiles effective bodies and assembles expanded source with provenance pieces.
4. Parses again and builds the semantic AST, returning a `WikitextCompilation` with `status`, `snapshot`, `dependencies` and `stats`.

The returned `snapshot` is already a normal parsed snapshot; **do not parse again**. Hand it to `prepareWikitext`.

## Template table provider

- Keys are parser-normalized titles. With the default config, `{{Box}}` requests `Template:Box`; `Box` and `box` do not match.
- Values must be strings; an empty string is a valid empty template.
- The table is validated and copied once at construction and reused by later compilations. Update it by creating a new `revision`; do not mutate the old object.
- Call titles are normalized by the parser (`{{Box}}` → `Template:Box`); the table lookup itself is exact and never rewrites your keys.

## Pure functions

When only pure functions are involved, the table may be empty:

```ts
const compilation = await compiler.compile({
  key: "page",
  revision: "1",
  text: "{{#if:1|yes|no}}",
});
```

Without any template source, template calls are treated as missing: preserved with `TEMPLATE_NOT_FOUND`, or thrown with `failureMode: "throw"`.

## Remote provider

`open` returns a snapshot fixed for one compilation:

```ts
const provider: WikitextTemplateProvider = {
  key: "site:example",
  open() {
    return {
      key: "site:example",
      revision: contentRevision,
      async get(title, request) {
        const response = await fetch(`/api/templates/${encodeURIComponent(title)}`, {
          signal: request.signal,
        });
        if (response.status === 404) {
          return null; // definitely missing
        }
        if (!response.ok) {
          throw new Error(`template fetch failed: ${response.status}`); // TEMPLATE_RESOLVE_FAILED
        }
        return { title, source: await response.text() };
      },
      async getMany(titles) {
        const response = await fetch("/api/templates/batch", {
          method: "POST",
          body: JSON.stringify(titles),
        });
        const payload = (await response.json()) as Record<string, string | null>;
        return new Map(
          titles.map((title) => [title, payload[title] ? { title, source: payload[title] } : null]),
        );
      },
      release() {
        // release per-session auth or connections; called once after success, failure or cancellation
      },
    };
  },
};
```

- `get` / `getMany` may be synchronous or return a Promise; pass `request.signal` to `fetch` so cancellation aborts requests.
- `null` means missing; `undefined` or a wrong type is a fetch failure. Thrown errors record `TEMPLATE_RESOLVE_FAILED`.
- A snapshot must return stable content for a title; content changes require a new `revision`.
- `getMany` results may arrive in any order but must be indexed by title; missing titles are fetch failures.
- One compilation uses exactly one snapshot; template edits during a session never mix versions.

## Scheduling and caching

- Evaluation advances in deterministic rounds; uncompiled templates are recorded as demands and deferred, then fetched in batches by `getMany` or within the concurrency cap and committed at fixed task addresses.
- Untaken branches, unread parameters and unused defaults never trigger fetches.
- Caches cover fetch results, template syntax programs and page syntax compilations; both entry count and bytes are bounded.
- Concurrent compiles share unfinished fetches for the same provider snapshot; cancelling one only removes that subscriber.
- Changing `cache`, `fetch` or `limits` requires a new compiler instance.

## Sources and lookup

```ts
import { mapSourceSpan, locateRenderedNode, findRenderedNodes } from "react-wikitext/ast";

const located = locateRenderedNode(compilation.snapshot, nodeId);
const nodes = findRenderedNodes(compilation.snapshot, {
  sourceId: compilation.snapshot.activeSourceId,
  start: 0,
  end: 10,
});
```

- The source graph records page input, LF text, template source, effective body and expanded text, plus piece relations and invocation records.
- Nested calls keep their own source, scope, parent and every output occurrence; one template range can map to multiple expanded positions.
- Exact mapping is only claimed for provable boundary correspondence; function results, generated characters and deleted ranges are `enclosing-invocation` or unmapped.
- Results include multiple matches, unmapped subranges and coverage; `truncated` marks the limit.

## Supported syntax and functions

- Transclusion with anonymous, named, default and dynamic parameters.
- `noinclude` / `includeonly` / `onlyinclude`.
- `#if`, `#ifeq`, `#switch`, `#iferror`, `#expr`, `#ifexpr`.
- `#len`, `#sub`, `#replace`, `#titleparts`, `#padleft`, `#padright`, `#urlencode`, `#urldecode`.
- `#lc`, `#uc`, `#lcfirst`, `#ucfirst`, `#trim`, `#tag`.
- `{{!}}` and `{{=}}`.
- Implicit newlines for template and function output.

Evaluation is lazy: template names, parameter names and conditions are evaluated only when their scope needs them. String lengths and slices count Unicode code points; source offsets remain UTF-16.

These calls are preserved with diagnostics by default:

- `#invoke` and Lua.
- Transclusion modifiers such as `subst`.
- Functions depending on site state or external runtime, such as `#ifexist` and `#time`.

## Budgets and failures

See [Expansion `/expand`](../api/expand.mdx) for defaults and full details.

- An over-long single call is preserved with `LENGTH_BUDGET_EXCEEDED`.
- The whole expanded text over `budget.maxExpandedLength` throws `EXPANSION_TOO_LARGE`.
- `failureMode: "throw"` turns recoverable failures and budget limits into errors.
- By default a failed final parse falls back to the original snapshot with `status: "fallback"`; `attemptedSourceId` points at the abandoned expanded source.
- Cancel via `AbortSignal`; the original reason is kept in `error.cause`.
- Original parse failures, hard resource limits and incompatible parsers always fail.

Common codes: `INVALID_EXPAND_OPTIONS`, `INVALID_PROVIDER`, `TEMPLATE_NOT_FOUND`, `TEMPLATE_RESOLVE_FAILED`, `TEMPLATE_PARSE_FAILED`, `TEMPLATE_LOOP`, `UNSUPPORTED_CALL`, `FINAL_PARSE_FAILED`, `ABORTED`, `DISPOSED`.

## How preserved calls render

Preserved templates, functions and parameters keep their [placeholder structure](./rendering.mdx). Template sources and expanded results are untrusted wikitext and still pass semantic normalization, HAST conversion and final sanitization.

## Limitations

- Include filtering covers mixed and nested combinations with regression tests, but is not a full site-level tag state machine.
- No Lua and no built-in site API client.
- No title normalization option; hosts curate template keys.
- Categories, references and TOC in expanded output still follow normal rendering rules.
