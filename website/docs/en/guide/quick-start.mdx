# Quick Start

This page renders a snippet. For pipeline, snapshot, and entry trade-offs, see [How it works](./concepts.mdx).

## Requirements

- React `>=18.2 <20` (peer dependency).
- `react-dom` is an optional peer dependency with the same range; install it for server rendering or hydration.
- Node `>=20.19` for builds or server execution; `>=22.13` with `engine-strict`.
- ESM and CJS builds; consumer builds with Vite and webpack 5 are covered by tests.
- No Wikimedia, font CDN, or external API dependency at runtime.

## Installation

| Package manager | Command                      |
| --------------- | ---------------------------- |
| pnpm            | `pnpm add react-wikitext`    |
| npm             | `npm install react-wikitext` |
| yarn            | `yarn add react-wikitext`    |

The stylesheet is imported once:

```ts
import "react-wikitext/styles.css";
```

## Minimal example

The `Wikitext` component from the root entry handles parsing, preparation, and rendering. Import the stylesheet once:

```tsx preview
import { Wikitext } from "react-wikitext";
import "react-wikitext/styles.css";

const source = `== Hello, wikitext ==
This paragraph mixes '''bold''', ''italic'', and an [[internal link|internal link]].

* First item
* Second item`;

export default function Article() {
  return <Wikitext source={source} lang="en" />;
}
```

`Wikitext` renders a root `div.wikitext-view`. `lang` and `dir` are written to that container for layout and assistive technology.

:::warning
`Wikitext` and `WikitextView` depend on React Context and only run in Client Components. The root entry and `/view` already ship a `"use client"` directive, so they can be used directly in Next.js App Router; the server should only call React-free entries such as `/parse` and `/hast`, as shown in [server preparation](./server-rendering.mdx).
:::

## What you get

By default:

- Headings, paragraphs, bold, italic, lists, definition lists, tables, code blocks, and references render as structured output.
- Internal links are non-navigable and files are placeholders; see [Links and images](./links-and-images.mdx) for how to wire them up.
- Templates, parser functions, and files render explicit placeholders; their content is not inferred.
- A table of contents is generated automatically once a page has four headings; categories are collected into a footer.
- Unknown structures degrade to source cards, so the page continues to render.

See [Syntax support](./syntax-support.mdx) for per-construct status and [Rendering behavior](./rendering.mdx) for details.
