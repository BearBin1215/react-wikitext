# React components

The root entry exports the source component `Wikitext` and the view components; hosts that render prepared snapshots should use [`/view`](./view.mdx), which does not load a parser.

:::warning
Components run only in Client Components; the root entry ships a `"use client"` directive. See [Server rendering and frameworks](../guide/server-rendering.mdx) for the full boundary and SSR usage.
:::

## Wikitext

```tsx
import { Wikitext } from "react-wikitext";
import "react-wikitext/styles.css";

<Wikitext source={source} lang="en" />;
```

The source component parses, prepares, and renders synchronously.

### Props

```ts
interface WikitextProps extends Omit<WikitextViewProps, "snapshot"> {
  source: string;
  parser?: WikitextParser;
  parseOptions?: WikitextParseOptions;
  prepareOptions?: WikitextPrepareOptions;
  onPrepared?: (snapshot: WikitextRenderSnapshot) => void;
  onError?: (error: WikitextError, info: { stage: "parse" | "prepare" }) => void;
  fallback?:
    | React.ReactNode
    | ((error: WikitextError, info: { stage: "parse" | "prepare" }) => React.ReactNode);
}
```

| Prop             | Description                                                                                                                                                                               |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `source`         | Wikitext source to render                                                                                                                                                                 |
| `parser`         | Reuse an existing parser; otherwise a shared default parser is used                                                                                                                       |
| `parseOptions`   | Parse options, see [`/parse`](./parse.mdx)                                                                                                                                                |
| `prepareOptions` | Prepare options, see [`/hast`](./prepare.mdx)                                                                                                                                             |
| `onPrepared`     | Called after a successful prepare; read `diagnostics`, `headings`, and settings                                                                                                           |
| `onError`        | Parse/prepare failure callback; `error` is always `WikitextError`, `info.stage` tells which stage                                                                                         |
| `fallback`       | Rendered on failure; takes over entirely and disables the built-in error container                                                                                                        |
| Other props      | Same as [`WikitextView`](./view.mdx#wikitextview): `components`, `semanticComponents`, `lang` / `dir`, `idPrefix`, `className`, `containerProps`, `sourceAttributes`, and `onRenderError` |

### Behavior

- Parsing and preparation are memoized with `[parser, source, parseOptions]` and `[parsed, prepareOptions]`; changing only `prepareOptions` reuses the previous parse.
- Passing new option objects on every render reruns the corresponding stage; keep references stable.
- Plugins and resolvers must be pure; async plugins throw `ASYNC_PLUGIN_IN_SYNC_PATH`.
- Importing `/parse` executes the upstream IIFE; the default parser instance is created lazily on first parse. Use `/view` when no parser is needed.
- Placeholders, blocks, and degradations are diagnostics on the snapshot and still render; read them through `onPrepared`, not `onError`.

## Error handling

```tsx
<Wikitext
  source={source}
  onRenderError={(error, { node }) => {
    reportError(error, { nodeType: node.type, nodeId: node.id });
  }}
/>
```

On parse or prepare failure, `fallback` takes over:

```tsx
<Wikitext
  source={source}
  onError={(error, info) => console.error(info.stage, error.code)}
  fallback={<p>Content failed to load</p>}
/>
```

The error boundary isolates top-level HAST blocks; see [view components](./view.mdx#render-errors) for block-level display and `onRenderError`. Parse and prepare failures never enter the boundary; they follow the callbacks you pass:

| Inputs                           | Behavior                                                                        |
| -------------------------------- | ------------------------------------------------------------------------------- |
| Neither `onError` nor `fallback` | Propagate to the outer error boundary                                           |
| Only `onError`                   | Render the built-in error container, using `prepareOptions.labels.renderFailed` |
| `fallback` provided              | It takes over entirely; returning `null` renders nothing                        |
