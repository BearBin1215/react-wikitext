# Entry Points

Capabilities are split by subpath so hosts can load only what they need. The root entry is the main entry; `react-wikitext/view` is a lightweight entry that does not load the parser. See [How it works](../guide/concepts.mdx) for the pipeline stages, the optional expansion step, and the two snapshot types.

## Subpaths

| Subpath                                     | Contents                                                                                                                               | Loads parser                 | Loads React |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- | ----------- |
| [`react-wikitext`](./react.mdx)             | `Wikitext`, `WikitextView`, `WikitextFragment`, context hooks, component types, selected semantic types                                | Yes                          | Yes         |
| [`react-wikitext/ast`](./ast.mdx)           | Semantic model, queries, helpers, pure parser factory, source normalization, serialization                                             | No                           | No          |
| [`react-wikitext/parse`](./parse.mdx)       | Default parser, `parseWikitext`, parse options, parse errors                                                                           | Yes                          | No          |
| [`react-wikitext/expand`](./expand.mdx)     | `createWikitextCompiler`, template providers, compilation types and errors                                                             | No (parser injected)         | No          |
| [`react-wikitext/preview`](./preview.mdx)   | `useWikitextPreview`, executor protocol, worker transport                                                                              | No                           | Yes         |
| [`react-wikitext/worker`](./worker.mdx)     | `createWikitextWorkerHandler`, `attachWikitextWorker`, message protocol                                                                | No (parser injected)         | No          |
| [`react-wikitext/hast`](./prepare.mdx)      | `prepareWikitext`, `prepareWikitextAsync`, resolvers, policy, labels, heading strategies, URL utilities, render snapshot serialization | No                           | No          |
| [`react-wikitext/unified`](./unified.mdx)   | `createWikitextProcessor`, a unified integration with a library-owned final sanitize stage                                             | No (parser must be injected) | No          |
| [`react-wikitext/view`](./view.mdx)         | `WikitextView`, `WikitextFragment`, context hooks, component types                                                                     | No                           | Yes         |
| [`react-wikitext/configs`](./configs.mdx)   | `MEDIAWIKI_CONFIG`, `createMediaWikiConfig`, `ParserConfig`                                                                            | No                           | No          |
| [`react-wikitext/devtools`](./devtools.mdx) | `AstTree`, `NodeInspector`, node range/source queries, selection restore helpers, and debug label types                                | No                           | Yes         |
| `react-wikitext/styles.css`                 | Page rendering styles                                                                                                                  | —                            | —           |
| `react-wikitext/tokens.css`                 | Theme variables only; import when overriding variables without duplicating view styles                                                 | —                            | —           |
| `react-wikitext/devtools.css`               | Debug component styles; includes theme variables                                                                                       | —                            | —           |

The root entry does not export the parse, expand, hast, unified, or devtools entry APIs; import them from the corresponding entries.

## Parse and render snapshots

- Parse snapshot `WikitextParsedSnapshot`: produced by `/parse`; field definitions are in [Parsing `/parse`](./parse.mdx).
- Render snapshot `WikitextRenderSnapshot`: produced by `/hast` preparation; field definitions are in [Preparation `/hast`](./prepare.mdx).

The `ast` in a parse snapshot is the original normalized result and is never mutated by preparation. The `ast` in a render snapshot is the working tree after plugins, with node ids reassigned. Its `hast` is sanitized and finalized, including the TOC, reference section, and category footer; `WikitextView` accepts only a render snapshot.

Query transformed nodes with the render snapshot. Do not use ids from the render snapshot to look up the original parse snapshot.

## How to choose

| Need                                        | Use                                   |
| ------------------------------------------- | ------------------------------------- |
| Render source directly on the client        | Root `Wikitext`                       |
| Prepare on the server, render on the client | `/parse` + `/hast` + `/view`          |
| Parse only or inspect the AST               | `/parse` + `/ast`                     |
| Debug parse results                         | `/parse` + `/devtools`                |
| Expand templates, then render               | `/expand` + `/hast` + `/view`         |
| Integrate with a unified processor          | `/unified` (inject parser explicitly) |
| Swap site configuration only                | `/configs` + `/parse`                 |

## Types and errors

- The error classes are exported from the root entry and the relevant feature entries; see [Errors and diagnostics](./errors.mdx) for the full matrix.
- The `WikitextLabels` type is available from `/ast` and `/view`; `DEFAULT_WIKITEXT_LABELS` and `DEFAULT_PREPARE_POLICY` come from `/hast`.
- Import the full set of node subtypes, `WikitextNodeBase`, `KnownWikitextDiagnosticCode`, and `WikitextStage` from `/ast`; the root entry exports only selected semantic types used by view props.
- `stage` and diagnostic fields are defined in [Errors and diagnostics](./errors.mdx).

Versions, schema versions, and runtime requirements are in [Status and compatibility](../project/status.mdx).
