# Errors and diagnostics

The library separates two kinds of signals:

- **Errors** (`Error`): the current call cannot continue, so it throws; the caller must catch it.
- **Diagnostics** (`WikitextDiagnostic`): a local problem or degradation recorded on the snapshot; it does not abort rendering.

## Error classes

```ts
class WikitextError extends Error {
  readonly code: WikitextErrorCode;
  readonly location?: WikitextSourceSpan;
  cause?: unknown;
}

class WikitextParseError extends WikitextError {}

class WikitextPrepareError extends WikitextError {
  readonly stage: WikitextStage;
}

class WikitextExpandError extends WikitextError {
  readonly templateTitle?: string;
}
```

Every error carries `code` and an optional `location` (text source plus `[start, end)`); `cause` keeps the underlying exception. `WikitextPrepareError.stage` shares `WikitextStage` with diagnostics.

## Exports per entry

All four classes are the same definitions, so `instanceof` works across entries; each entry exports only the classes its stage needs:

| Entry                                       | Exports                                                                                       |
| ------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Root entry                                  | All four error classes, `WikitextErrorCode`, `WikitextExpandErrorCode`                        |
| `/parse`, `/ast`                            | `WikitextError`, `WikitextParseError`, `WikitextErrorCode`                                    |
| `/expand`                                   | `WikitextError`, `WikitextExpandError`, `WikitextExpandErrorCode`                             |
| `/hast`                                     | `WikitextError`, `WikitextPrepareError`                                                       |
| `/view`, `/devtools`, `/preview`, `/worker` | No error classes; failures surface as plain `Error`, executor rejections or protocol payloads |

## Error codes

| Code                        | Stage           | Trigger                                                             |
| --------------------------- | --------------- | ------------------------------------------------------------------- |
| `SOURCE_TOO_LONG`           | Parse           | Normalized source exceeds the length budget                         |
| `SOURCE_TOO_COMPLEX`        | Parse           | Syntax or semantic tree exceeds node/depth budgets                  |
| `INVALID_CONFIG`            | Parse           | Site config or budget fields are invalid                            |
| `PARSE_FAILED`              | Parse           | Upstream parse or semantic build failed                             |
| `PARSER_UNAVAILABLE`        | Parse           | The browser bundle did not initialize the global parser             |
| `PREPARE_FAILED`            | Prepare         | Options, plugins, handlers, or budgets fail validation              |
| `ASYNC_PLUGIN_IN_SYNC_PATH` | Prepare         | A synchronous entry encountered an async plugin                     |
| `INVALID_DOCUMENT`          | Restore/Prepare | Snapshot structure, version, root, or budgets are invalid           |
| `INVALID_EXPAND_OPTIONS`    | Expand          | Compile options or budget fields are invalid                        |
| `INCOMPATIBLE_PARSER`       | Expand          | The injected parser cannot support expansion                        |
| `TEMPLATE_NOT_FOUND`        | Expand          | The template does not exist                                         |
| `TEMPLATE_RESOLVE_FAILED`   | Expand          | The provider failed or returned an invalid type                     |
| `TEMPLATE_PARSE_FAILED`     | Expand          | The template source could not be compiled                           |
| `TEMPLATE_LOOP`             | Expand          | The template body recurses along its lexical ancestor path          |
| `UNSUPPORTED_CALL`          | Expand          | Unsupported function, Lua, or transclusion modifier                 |
| `UNRESOLVED_DEPENDENCY`     | Expand          | Demand rounds do not converge or an argument cannot resolve         |
| `EXPANSION_BUDGET_EXCEEDED` | Expand          | Invocation or template count exceeds the budget                     |
| `EXPANSION_TOO_LARGE`       | Expand          | Expanded or preserved source exceeds the length limit               |
| `FINAL_PARSE_FAILED`        | Expand          | Expanded source cannot be parsed again (`failureMode: "throw"`)     |
| `SOURCE_GRAPH_TOO_LARGE`    | Expand          | Source graph exceeds source, segment, or invocation limits          |
| `INVALID_PROVIDER`          | Expand          | The provider did not return a valid template snapshot               |
| `INVALID_PREVIEW_OPTIONS`   | Preview         | Preview debounce, request identity, or executor options are invalid |
| `ABORTED`                   | Expand          | Cancelled through `AbortSignal`                                     |
| `DISPOSED`                  | Lifecycle       | The compiler or worker was used after disposal                      |

The default `failureMode: "preserve"` keeps failed calls and records diagnostics, with a `partial` compilation status; `failureMode: "throw"` turns the recoverable failures above into throws. Original parse failures, hard resource limits, cancellation, and incompatible parsers always fail regardless of `failureMode`.

## Handling examples

```ts
import { WikitextParseError } from "react-wikitext/parse";

try {
  const parsed = parser.parse(source, { pageName: "Example" });
  return parsed;
} catch (error) {
  if (error instanceof WikitextParseError) {
    if (error.code === "SOURCE_TOO_LONG") {
      return loadSourceInPages(source);
    }
    throw error;
  }
  throw error;
}
```

```ts
import { prepareWikitextAsync, WikitextPrepareError } from "react-wikitext/hast";

try {
  return await prepareWikitextAsync(parsed, { rehypePlugins });
} catch (error) {
  if (error instanceof WikitextPrepareError) {
    report(error.code, error.stage, error.cause);
  }
  throw error;
}
```

- Do not branch on `message`; use `code` (plus `stage` when needed).
- Catch parse and prepare errors at the call site and distinguish budgets, config, and plugin failures.
- Render failures surface through `onRenderError`; the error boundary replaces only the failing top-level block.
- A failed restore must not silently degrade to a reparse; check the version and sources first.

## Diagnostics

`KnownWikitextDiagnosticCode` is the fixed vocabulary, exported from `/ast`, `/parse`, `/hast`, and the root entry; `WikitextDiagnosticCode` also accepts plugin-defined strings.

```ts
type KnownWikitextDiagnosticCode =
  | "UNKNOWN_NODE"
  | "EXTENSION_UNSUPPORTED"
  | "NESTED_TABLE_UNSUPPORTED"
  | "TABLE_FILLER_BUDGET_EXCEEDED"
  | "FILE_PLACEHOLDER"
  | "BEHAVIOR_SWITCH_IGNORED"
  | "BLOCKED_HTML"
  | "UNAUTHORIZED_IMAGE"
  | "STYLE_DECLARATION_DROPPED"
  | "REFERENCE_DUPLICATE_DEFINITION"
  | "REFERENCE_MISSING_CONTENT"
  | "UNSUPPORTED_CALL"
  | "UNRESOLVED_DEPENDENCY"
  | "TEMPLATE_NOT_FOUND"
  | "TEMPLATE_LOOP"
  | "TEMPLATE_RESOLVE_FAILED"
  | "TEMPLATE_PARSE_FAILED"
  | "DEPTH_BUDGET_EXCEEDED"
  | "INVOCATION_BUDGET_EXCEEDED"
  | "LENGTH_BUDGET_EXCEEDED"
  | "EXPRESSION_ERROR"
  | "FINAL_PARSE_FALLBACK"
  | "UNCLOSED_CALL"
  | "SOURCE_GRAPH_BUDGET_EXCEEDED"
  | "TEMPLATE_BUDGET_EXCEEDED";

type WikitextDiagnosticCode = KnownWikitextDiagnosticCode | (string & {});

interface WikitextDiagnostic {
  readonly code: WikitextDiagnosticCode;
  readonly stage: WikitextStage;
  readonly severity: "error" | "warning" | "info";
  readonly message: string;
  readonly location?: WikitextSourceSpan;
  readonly related?: readonly WikitextRelatedLocation[];
  readonly invocationId?: string;
  readonly templateTitle?: string;
  readonly count?: number;
  readonly rule?: string;
}
```

- `stage` shares `WikitextStage` with errors and includes `parse`, `expand`, `prepare`, `wikitext`, `hast`, `rehype`, `sanitize`, and `finalize`.
- `severity` describes content damage, not call failure: `error` may still be a successful page render (for example `FINAL_PARSE_FALLBACK`). Only a thrown `WikitextError` fails the call; do not use `severity === "error"` as a request-failure check.
- `location` points at the text source where the failure happened; when a template body fails, it points at the template's effective body and the page call site goes into `related`.
- `invocationId` maps to `snapshot.graph.invocations`; `templateTitle` only appears on expansion diagnostics.
- Generated content may have no `location`; `count` only appears on aggregated diagnostics.
- `rule` identifies the rule or plugin that produced the diagnostic.
- A render snapshot's `diagnostics` merges parse, prepare, and finalize records.
- A single diagnostic never aborts the page; reporting or blocking is up to the host. `<Wikitext>` exposes them through `onPrepared`.

## Reading diagnostics in components

```tsx
<Wikitext
  source={source}
  onPrepared={(snapshot) => {
    for (const diagnostic of snapshot.diagnostics) {
      reportDiagnostic(diagnostic);
    }
  }}
  onError={(error) => reportFailure(error.code, error.cause)}
/>
```

`onPrepared` runs only after a successful prepare; `onError` handles parse or prepare failures, and the two never report the same event twice.
