# View components `/view`

```tsx
import { WikitextView } from "react-wikitext/view";
```

`/view` loads only React and a prepared snapshot; it does not load a parser, the preparation stage, or plugins. The source component lives in [React components](./react.mdx).

:::warning
View components run only in Client Components; the `/view` output ships a `"use client"` directive. See [Server rendering and frameworks](../guide/server-rendering.mdx) for the full boundary and SSR usage.
:::

## WikitextView

```tsx
<WikitextView snapshot={prepared} lang="en" />
```

`WikitextView` accepts only a prepared render snapshot. It never parses source, runs plugins, or calls resolvers while rendering. A lightweight runtime check rejects a parsed snapshot with `WikitextError("INVALID_DOCUMENT")` instead of silently rendering nothing.

### Props

| Prop                 | Description                                                                    |
| -------------------- | ------------------------------------------------------------------------------ |
| `snapshot`           | Prepared `WikitextRenderSnapshot`; a parsed snapshot throws `INVALID_DOCUMENT` |
| `components`         | Override by HAST tag name                                                      |
| `semanticComponents` | Override by wiki semantic type                                                 |
| `lang` / `dir`       | Language and direction on the root container                                   |
| `idPrefix`           | Instance prefix for `instance` strategy; defaults to `useId`                   |
| `className`          | Merged with `wikitext-view`                                                    |
| `containerProps`     | Root attributes; `dangerouslySetInnerHTML` is excluded                         |
| `sourceAttributes`   | `"none"` / `"block"` / `"all"`; emits `data-wikitext-*` source attributes      |
| `onRenderError`      | Block-level render error callback                                              |

- The root is always `div.wikitext-view`.
- `idPrefix` is sanitized to `[A-Za-z0-9_-]` and truncated to 128 characters; an empty result falls back to `useId`. It affects heading ids, in-document `#fragment` links, and table `headers`.
- Each top-level block is wrapped in an error boundary; one failing block does not affect the others.
- The view builds semantic and HAST indexes for components and `WikitextFragment`.

## WikitextFragment

```tsx
import { WikitextFragment } from "react-wikitext/view";

<WikitextFragment nodes={node.children} mode="block" />;
```

| Prop        | Description                            |
| ----------- | -------------------------------------- |
| `nodes`     | Semantic nodes from the current render |
| `mode`      | `"inline"` (default) or `"block"`      |
| `className` | Optional outer class                   |

- Must be used inside a `<WikitextView>` context, otherwise it throws.
- `nodes` must be the **same node objects** from the current render; matching ids alone is not enough.
- Only nodes present in the prepared HAST index render; this suits template arguments, file captions, and `ref` content.
- Inline mode adds no wrapper without `className`, uses `<span>` with one, and block mode uses a `wikitext-fragment` container.
- Rendering the same node twice in one view duplicates content and heading ids.

## Component overrides

### HTML components

```ts
type WikitextHtmlComponents = Partial<
  Record<string, React.ComponentType<WikitextHtmlComponentProps>>
>;

interface WikitextHtmlComponentProps extends React.HTMLAttributes<HTMLElement> {
  node?: import("hast").Element;
  snapshot: WikitextRenderSnapshot;
  semantic?: WikitextNode;
  origin?: WikitextOrigin;
  children?: React.ReactNode;
  href?: string;
  src?: string;
  alt?: string;
}
```

Mapped by tag name such as `p`, `table`, `img`, or `a`. Components receive sanitized DOM props plus the HAST element, the snapshot, and an optional semantic node.

### Semantic components

```ts
type WikitextSemanticComponents = {
  link?: React.ComponentType<WikitextLinkComponentProps>;
  template?: React.ComponentType<WikitextTemplateComponentProps>;
  parserFunction?: React.ComponentType<WikitextTemplateComponentProps>;
  argument?: React.ComponentType<WikitextSemanticComponentProps<WikitextArgument>>;
  file?: React.ComponentType<WikitextFileComponentProps>;
  reference?: React.ComponentType<WikitextReferenceComponentProps>;
  extension?: React.ComponentType<WikitextExtensionComponentProps>;
  unknown?: React.ComponentType<WikitextUnknownComponentProps>;
  table?: React.ComponentType<WikitextSemanticComponentProps<WikitextTable>>;
};
```

Every semantic component receives:

```ts
interface WikitextSemanticComponentProps<Node extends WikitextNode> {
  snapshot: WikitextRenderSnapshot;
  node: Node;
  hastNode: import("hast").Element;
  origin?: WikitextOrigin;
  children?: React.ReactNode;
}
```

Additional fields:

| Type                          | Extra props                           |
| ----------------------------- | ------------------------------------- |
| `link`                        | `target`, `kind`, `href?`, `external` |
| `template` / `parserFunction` | `displayName`                         |
| `argument`                    | —                                     |
| `file`                        | `name`                                |
| `reference`                   | `number`                              |
| `extension`                   | `name`, `block`                       |
| `unknown`                     | `parsedType`, `block`                 |
| `table`                       | —                                     |

Precedence: an explicit semantic component replaces the whole semantic structure; otherwise `components` still apply inside the default HAST; finally native elements are used.

### Custom links

```tsx
<WikitextView
  snapshot={prepared}
  semanticComponents={{
    link: ({ href, external, children }) =>
      href ? (
        <a href={href} {...(external ? { rel: "nofollow" } : {})}>
          {children}
        </a>
      ) : (
        <span className="unresolved-link">{children}</span>
      ),
  }}
/>
```

## Context hooks

```ts
interface WikitextViewContextValue {
  snapshot: WikitextRenderSnapshot;
  semanticIndex: ReadonlyMap<string, WikitextNode>;
  hastIndex: ReadonlyMap<string, import("hast").ElementContent>;
  components: WikitextHtmlComponents;
  semanticComponents: WikitextSemanticComponents;
  idPrefix: string;
  mapId: (id: string) => string;
  mapHref: (href: string) => string;
  onRenderError?: (error: Error, info: { node: WikitextNode }) => void;
}

function useWikitextContext(): WikitextViewContextValue;
function useWikitextLabels(): WikitextLabels;
function useWikitextIds(): { toDomId(id: string): string; toHref(href: string): string };
```

- These hooks must run inside `<WikitextView>`.
- `useWikitextLabels()` reads the final labels on the render snapshot.
- `useWikitextIds()` is useful when custom components generate anchors or fragment links.

## Render errors

The error boundary isolates each top-level HAST block: one failure does not affect the rest, the placeholder shows `labels.renderFailed`, the node type, and its source, and `onRenderError` reports it.

Parse and prepare failures never enter the error boundary: without `onError` or `fallback` they propagate to the outer boundary. See [React components](./react.mdx#error-handling) for the source component.

## Related types

`/view` exports the component prop types used above. The selected semantic types (`WikitextLink`, `WikitextTemplate`, `WikitextFile`, `WikitextReference`, `WikitextTable`, `WikitextUnknown`, and others) are exported by the root entry; import full node subtypes and AST helpers from [`/ast`](./ast.mdx).

To inspect parse or render results, use `AstTree` and `NodeInspector` from [`/devtools`](./devtools.mdx); they read the same snapshot and stay out of the render path.
