# 模板展开

默认管线不执行模板。需要模板结果时，用 `/expand` 的编译器在解析前展开受支持的模板与解析器函数。库不发起网络请求，模板源码由宿主提供：离线内容、随应用一起提供的源码或预加载的模板集合可以直接用模板表 provider；需要按需获取时提供自定义 provider。

## 基本用法

```tsx
import { createTemplateTableProvider, createWikitextCompiler } from "react-wikitext/expand";
import { prepareWikitext } from "react-wikitext/hast";
import { WikitextView } from "react-wikitext/view";
import "react-wikitext/styles.css";

const provider = createTemplateTableProvider({
  key: "offline:example",
  revision: "templates-v1",
  templates: {
    "Template:Note": "'''{{{1|默认说明}}}'''",
    "Template:Empty": "",
  },
});

const compiler = createWikitextCompiler({ parser, provider });

const compilation = await compiler.compile(
  { key: "page:example", revision: "edit-1", text: "{{Note|离线内容}}{{Empty}}" },
  { pageName: "Example" },
);

const prepared = prepareWikitext(compilation.snapshot);
const view = <WikitextView snapshot={prepared} lang="zh-CN" />;
```

下面的预览对照默认管线与展开后的结果：左侧是尚未展开的模板占位，右侧是同一份源码经编译器展开并重新准备后的渲染结果。

```tsx preview
import { useEffect, useMemo, useState } from "react";
import { createTemplateTableProvider, createWikitextCompiler } from "react-wikitext/expand";
import { prepareWikitext, type WikitextRenderSnapshot } from "react-wikitext/hast";
import { createWikiparser, parseWikitext } from "react-wikitext/parse";
import { WikitextView } from "react-wikitext/view";
import "react-wikitext/styles.css";

const source = `'''模板展开'''会把模板调用替换为模板源码，再重新解析。

{{Note|模板参数}}

{{List}}

{{#if:1|条件为真|条件为假}}`;

const provider = createTemplateTableProvider({
  key: "demo",
  revision: "v1",
  templates: {
    "Template:Note": "'''说明：'''{{{1|缺少参数}}}",
    "Template:List": "* 第一项\n* 第二项",
  },
});

const before = prepareWikitext(parseWikitext(source, { pageName: "Demo" }));
const pane = { flex: 1, minWidth: 0 };
const label = { margin: "0 0 8px", fontSize: 13, color: "#57606a" };

export default function Demo() {
  const compiler = useMemo(
    () => createWikitextCompiler({ parser: createWikiparser(), provider }),
    [],
  );
  const [after, setAfter] = useState<WikitextRenderSnapshot | null>(null);
  const [status, setStatus] = useState("");
  const [error, setError] = useState("");

  useEffect(() => {
    const controller = new AbortController();
    compiler
      .compile(
        { key: "demo", revision: "1", text: source },
        { pageName: "Demo", signal: controller.signal },
      )
      .then((compilation) => {
        if (!controller.signal.aborted) {
          setAfter(prepareWikitext(compilation.snapshot));
          setStatus(
            `状态 ${compilation.status}，${compilation.snapshot.graph.invocations.length} 条调用记录`,
          );
        }
      })
      .catch((reason) => {
        if (!controller.signal.aborted) {
          setError(reason instanceof Error ? reason.message : String(reason));
        }
      });
    return () => controller.abort();
  }, [compiler]);

  return (
    <div style={{ display: "flex", flexWrap: "wrap", gap: 16, alignItems: "flex-start" }}>
      <section style={pane}>
        <p style={label}>默认管线：模板占位</p>
        <WikitextView snapshot={before} lang="zh-CN" />
      </section>
      <section style={pane}>
        <p style={label}>{error ? error : after ? `展开后：${status}` : "展开中…"}</p>
        {after ? <WikitextView snapshot={after} lang="zh-CN" /> : null}
      </section>
    </div>
  );
}
```

`compiler.compile` 会：

1. 归一化换行并登记 `input` / `normalized` 文本源。
2. 只编译页面的调用结构，按确定顺序的需求轮次求值模板与函数。
3. 批量获取未编译的模板，编译有效正文，装配带来源片段的展开源码。
4. 重新解析并构建语义 AST，返回 `WikitextCompilation`：`status`、`snapshot`、`dependencies` 与 `stats`。

返回的 `snapshot` 已经是普通解析快照；**不需要再次解析**，直接交给 `prepareWikitext`。

## 模板表 provider

```ts
const provider = createTemplateTableProvider({
  key: "site:example",
  revision: "templates-v1",
  templates: {
    "Template:Note": "说明",
  },
});
```

- 键是 parser 规范化后的页面标题。默认配置下，`{{Box}}` 请求 `Template:Box`；`Box`、`box` 不会被匹配。其他命名空间的嵌入或自定义 parser 配置应使用实际请求的完整标题。
- 值必须是字符串，空字符串是合法模板（展开为空）。
- 构造时校验并复制一次；后续编译复用这份副本。更新表必须构造新的 `revision`，不要修改原对象冒充新版本。
- 模板表只按请求标题精确匹配，不做标题转换。

## 纯函数

只展开 `#if` 等受支持的纯 wikitext 函数时，模板表可以为空：

```ts
const compilation = await compiler.compile({
  key: "page",
  revision: "1",
  text: "{{#if:1|有值|空}}",
});
```

没有模板来源时，模板调用按缺失处理：默认保留调用并记录 `TEMPLATE_NOT_FOUND`；`failureMode: "throw"` 时抛错。

## 远程 provider

需要按需获取时实现自己的 provider。`open` 返回一次编译固定使用的快照：

```ts
const provider: WikitextTemplateProvider = {
  key: "site:example",
  open() {
    return {
      key: "site:example",
      revision: contentRevision,
      async get(title, request) {
        const response = await fetch(`/api/templates/${encodeURIComponent(title)}`, {
          signal: request.signal,
        });
        if (response.status === 404) {
          return null; // 模板确实不存在
        }
        if (!response.ok) {
          throw new Error(`模板获取失败：${response.status}`); // 记录 TEMPLATE_RESOLVE_FAILED
        }
        return { title, source: await response.text() };
      },
      async getMany(titles) {
        const response = await fetch("/api/templates/batch", {
          method: "POST",
          body: JSON.stringify(titles),
        });
        const payload = (await response.json()) as Record<string, string | null>;
        return new Map(
          titles.map((title) => [title, payload[title] ? { title, source: payload[title] } : null]),
        );
      },
      release() {
        // 释放本次会话的鉴权或连接；成功、失败与取消都会调用一次
      },
    };
  },
};
```

- `get` / `getMany` 可以同步返回，也可以返回 Promise；把 `request.signal` 传给 `fetch`，取消编译时请求会被中断。
- `null` 表示模板不存在；`undefined` 或类型不符按获取失败处理。抛出异常记录 `TEMPLATE_RESOLVE_FAILED`。
- 同一快照对同一标题必须返回稳定内容；内容变化必须更换 `revision`。
- `getMany` 返回顺序可以不同，但必须按标题索引结果；缺少请求标题按获取失败处理。
- 一次编译只使用同一个快照，编辑期间模板更新不会把两个版本混入一个结果。

## 调度与缓存

- 求值按确定顺序推进：需要未编译模板时记录需求并推迟本轮；调度器按 provider 快照去重、按 `getMany` 批大小或并发上限获取，再按固定任务地址提交。
- 未选中的分支、未读取的参数与未使用的默认值不会触发获取。
- 缓存分三层：模板获取结果、模板语法程序、页面语法编译；条目数与字节数同时受限。
- 并发编译共享同一 provider 快照的未完成获取；取消某次编译只移除该订阅者，全部订阅者取消后才中断底层请求。
- 修改 `cache` / `fetch` / `limits` 需要创建新的编译器实例。

## 来源与定位

```ts
import { mapSourceSpan, locateRenderedNode, findRenderedNodes } from "react-wikitext/ast";

const located = locateRenderedNode(compilation.snapshot, nodeId);
const nodes = findRenderedNodes(compilation.snapshot, {
  sourceId: compilation.snapshot.activeSourceId,
  start: 0,
  end: 10,
});
```

- 来源图登记页面原文、LF 文本、模板原文、有效正文与展开结果之间的片段关系与调用记录。
- 嵌套调用各自保存自身文本源、作用域、父调用与全部输出出现位置；同一模板的源码范围可以对应多个展开位置。
- 精确映射只用于可证明的边界对应；函数结果、生成内容与被删除片段返回 `enclosing-invocation` 或未映射。
- 映射结果包含多段匹配、未映射子范围与覆盖率；达到上限时 `truncated` 为 `true`。

## 支持的语法与函数

- 模板嵌入与参数替换：匿名参数、具名参数、参数默认值与动态参数名。
- `noinclude` / `includeonly` / `onlyinclude`。
- `#if`、`#ifeq`、`#switch`、`#iferror`、`#expr`、`#ifexpr`。
- `#len`、`#sub`、`#replace`、`#titleparts`、`#padleft`、`#padright`、`#urlencode`、`#urldecode`。
- `#lc`、`#uc`、`#lcfirst`、`#ucfirst`、`#trim`、`#tag`。
- `{{!}}` 与 `{{=}}`。
- 模板与函数输出的隐式换行。

按需计算：模板名、参数名与条件表达式只在所属作用域需要时求值。字符串长度与截取按 Unicode 码点计算，源码 offset 仍按 UTF-16 表示。

以下调用默认保留原文并产生诊断：

- `#invoke` 与 Lua。
- `subst` 等嵌入修饰符。
- 依赖站点状态或外部运行环境的函数，例如 `#ifexist`、`#time`。

## 预算与失败

默认值与完整说明见[展开 `/expand`](../api/expand.mdx)。

- 单次调用超长时保留调用并记录 `LENGTH_BUDGET_EXCEEDED`。
- 整段展开超过 `budget.maxExpandedLength` 时抛 `EXPANSION_TOO_LARGE`。
- `failureMode: "throw"` 下可恢复失败与预算超限直接抛错。
- 默认模式下，最终源码解析失败会退回原始快照，`status` 为 `"fallback"`；`attemptedSourceId` 指向被放弃的展开源。
- 通过 `AbortSignal` 取消编译；原始原因保存在错误的 `cause` 中。
- 原始解析失败、硬资源上限与不兼容 parser 始终失败。

常见错误码包括 `INVALID_EXPAND_OPTIONS`、`INVALID_PROVIDER`、`TEMPLATE_NOT_FOUND`、`TEMPLATE_RESOLVE_FAILED`、`TEMPLATE_PARSE_FAILED`、`TEMPLATE_LOOP`、`UNSUPPORTED_CALL`、`FINAL_PARSE_FAILED`、`ABORTED`、`DISPOSED`。

## 未展开的调用如何显示

展开失败保留的模板、函数与参数继续按[占位结构](./rendering.mdx)渲染，不会显示成已求值内容。模板源码与展开结果都按不可信 wikitext 处理，仍会经过语义归一化、HAST 转换与最终清洗。

## 限制

- include 标签过滤按模板嵌入模式处理；混合与嵌套组合有回归用例，但不是完整的站点嵌套标签状态机。
- 不执行 Lua，不内置站点 API 客户端。
- 不提供标题规范化选项；需要时由宿主整理模板键。
- 展开结果中的分类、引用、目录等仍按默认渲染规则处理。
