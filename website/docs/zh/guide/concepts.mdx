# 工作原理

库把渲染拆成可以分别部署的阶段。理解这条管线和快照类型，就能判断什么时候该用根入口，什么时候该把解析放到服务端。

## 处理管线

```text
source
  ├─ /parse ──────────────▶ WikitextParsedSnapshot ──────────────┐
  │                                                              │
  └─ /expand ────────────▶ WikitextCompilation.snapshot ────────┤
                                                                 ▼
/hast prepare ─▶ WikitextRenderSnapshot
  │
  ▼
/view ─▶ React
```

`/expand` 是可选阶段；`WikitextParsedSnapshot` 是解析快照，`WikitextRenderSnapshot` 是渲染快照。

| 阶段 | 入口                                               | 输入                        | 输出                            | 是否必需   |
| ---- | -------------------------------------------------- | --------------------------- | ------------------------------- | ---------- |
| 展开 | `/expand`                                          | 源码、页面名与模板 provider | 编译结果，`snapshot` 为解析快照 | 可选       |
| 解析 | `/parse`（`/ast` 提供自定义 adapter 的解析器工厂） | 源码                        | `WikitextParsedSnapshot`        | 必需       |
| 准备 | `/hast`                                            | 解析快照                    | `WikitextRenderSnapshot`        | 渲染前必需 |
| 渲染 | `/view`、根入口                                    | 渲染快照                    | React 元素                      | 渲染时必需 |

`compilation.snapshot` 已经是解析快照，不需要再解析一次；直接交给 `prepareWikitext`。使用 `/expand` 时不再单独调用 `/parse`，编译器内部的解析结果就是最终快照。

## 快照类型

### 解析快照 `WikitextParsedSnapshot`

字段定义见[解析 `/parse`](../api/parse.mdx)。

- `ast` 是归一化后的语义树，准备阶段不会修改它。
- `syntax` 只在 `retainSyntax: true` 时存在，是上游 token 的调试视图；语义节点的 `origin`、源码定位与查询函数都不依赖它。
- 同一份源码配合不同的站点配置或 `pageName`，可能得到不同的 AST。

### 渲染快照 `WikitextRenderSnapshot`

字段定义见[准备 `/hast`](../api/prepare.mdx)。

- `hast` 已经包含目录、引用区与分类底栏，不需要在视图层再拼装。
- `ast` 是本次工作树的结果，节点 id 已经重新分配。
- `meta` 记录实际生效的策略、文案、标题策略与授权图片。
- `WikitextView` 只接受渲染快照，不接收源码。

查询节点时必须区分两份快照：不要用渲染快照里的 id 查原始解析快照。

## 为什么要拆成两段

解析成本高，而准备选项经常变化。缓存解析快照，就可以用不同的解析回调、图片、文案或插件重复准备，而不必重新解析。服务端准备、客户端渲染也是同一套快照：客户端不加载解析器，也不重新执行插件。

准备阶段在克隆的工作树上执行，原始快照保持只读。快照是普通数据，可以放进缓存、跨 Worker 传递或经网络传输；恢复函数会重新校验结构与预算。两份快照都带同一份来源图，语义节点、诊断与 HAST 属性共用一套文本源与 span，跨模板展开、CRLF 归一化与插件改写仍能定位到实际源码。

:::note 说明
准备阶段不可跳过。它决定 HAST 的最终内容与安全边界；跳过准备、直接把 HAST 交给视图不在支持范围内。
:::

## 语义归一化

上游解析器给出的是源码语法树，库在语义阶段把它归一化为语义 AST。

无法安全或正确表达的结构会降级为源码卡片并写入诊断，不推断外观。模板、解析器函数、参数与文件默认输出占位，避免把“未求值”误当成“已求值”。

源码 HTML 按类别处理：允许的标签按白名单输出，禁止的标签整对丢弃并提示，未知标签降级。链接与图片在最终整理阶段再次校验协议、`target`、`rel` 与图片授权。

每处输出都能查到对应来源，便于排查和审计；与 Wikipedia 原站的排版会有差异。

## 入口与加载边界

各子路径的内容、是否加载解析器或 React，以及典型用途见[入口总览](../api/index.mdx#子路径)；逐个符号的清单见各入口的导出说明。

:::warning 警告

- React 入口使用 `useId` / `useMemo` 等 Hook，只能在客户端组件中运行。
- 根入口、`/view`、`/preview` 与 `/devtools` 的产物带 `"use client"`，在 Next.js App Router 等环境中可以直接使用。
- 服务端与构建期只使用 `/parse`、`/expand`、`/hast` 等无 React 入口；`/worker` 在 Worker 中使用。
  :::

## 术语

| 术语     | 含义                                                                                                            |
| -------- | --------------------------------------------------------------------------------------------------------------- |
| wikitext | MediaWiki 风格的页面源码                                                                                        |
| 解析快照 | 某份源码加上站点配置后的语义结果，对应 `WikitextParsedSnapshot`                                                 |
| 渲染快照 | 完成插件、HAST 转换、清洗与整理后的结果，对应 `WikitextRenderSnapshot`                                          |
| 来源图   | 快照内登记全部文本源、片段关系与调用记录的结构，供映射与定位查询                                                |
| 解析回调 | 宿主提供的 `resolveLink`、`resolveImage` 等回调，用于把 wiki 地址换成站点地址；不要与 wikitext 的解析器函数混淆 |
| 模板表   | `/expand` 的模板 provider 实现，按标题直接提供模板源码                                                          |
| 远程提供 | 自定义 `provider.open()` 返回的快照，按需批量获取模板源码                                                       |
| 转换函数 | `prepareOptions.handlers` 中把自定义语义节点转换为 HAST 的函数                                                  |
| 策略     | `prepareOptions.policy` 中的 URL、标签与类名规则                                                                |
| 文案     | `prepareOptions.labels`，所有用户可见占位与提示                                                                 |
