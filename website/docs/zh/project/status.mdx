# 状态与兼容性

## 版本状态

| 项目     | 当前状态                                                                                     |
| -------- | -------------------------------------------------------------------------------------------- |
| 安装     | npm 包                                                                                       |
| 稳定性   | 0.x 阶段按语义化版本约定，次版本可能包含破坏性变更                                           |
| 变更记录 | 以 [GitHub Releases](https://github.com/BearBin1215/react-wikitext/releases) 为准            |
| 文档站   | [react-wikitext.pages.dev](https://react-wikitext.pages.dev)，与主分支同步；不提供按版本切换 |

安装步骤见[快速开始](../guide/quick-start.mdx)。

## 运行时兼容

| 项目         | 支持范围                                                  |
| ------------ | --------------------------------------------------------- |
| React        | `>=18.2 <20`（peer dependency）                           |
| React DOM    | `>=18.2 <20`；可选 peer，服务端渲染或 hydration 时安装    |
| Node         | 安装与运行 `>=20.19`；启用 `engine-strict` 时需 `>=22.13` |
| 模块格式     | ESM 与 CJS，均提供类型声明                                |
| 打包器       | Vite 与 webpack 5 的消费者构建有测试覆盖                  |
| 浏览器       | 产物语法目标为 ES2022；不支持 IE 或更老的浏览器           |
| 运行环境依赖 | 不依赖 Wikimedia、字体 CDN 或外部 API                     |

Node 下限来自依赖链路：`wikiparser-node` 声明 `^20.19.0 || ^22.13.0 || >=24.11.0`，其传递依赖 `@bhsd/stylelint-util` 要求 `^22.13.0 || >=24.11.0`。默认安装在版本不满足时只给出警告，启用 `engine-strict` 会直接失败，因此该场景需要 Node `>=22.13`。

发布包包含 `dist/`、`NOTICE` 与 `THIRD_PARTY_LICENSES`；npm 还会附带 README 与 LICENSE。从源码构建与本地调试流程见[贡献指南](./contributing.mdx)。

## 固定的上游

| 项目         | 值                                               |
| ------------ | ------------------------------------------------ |
| 解析器       | `wikiparser-node@1.48.2`                         |
| 默认站点配置 | `MEDIAWIKI_CONFIG`，来源为同一版本的站点配置快照 |

升级解析器会改变 AST、源码范围与渲染基线，需要重新审查渲染与安全测试。

## 快照版本

| 常量                    | 当前值 | 适用       |
| ----------------------- | ------ | ---------- |
| `AST_SCHEMA_VERSION`    | `2`    | 语义 AST   |
| `SYNTAX_SCHEMA_VERSION` | `1`    | 源码语法树 |
| `RENDER_SCHEMA_VERSION` | `3`    | 渲染快照   |

版本变化意味着快照结构不兼容。缓存与跨进程传输时应把版本写入键；恢复函数会拒绝不匹配的数据。

## 版本与兼容策略

- 0.x 期间，破坏性的公开变化进入新的次版本系列；兼容修复留在当前次版本系列。
- 进入 1.x 后，已公开子路径、导出、参数含义与判别联合的既有成员保持兼容；删除或改名导出、收窄类型、改变字段含义以及使已承诺的官方快照不可恢复属于破坏性变化。新增判别联合成员也要检查消费者的穷尽匹配。
- 各个 schema 独立维护，只在数据结构或解释规则不兼容时各自递增；parser 升级不自动递增 schema，升级时需要重新运行快照与渲染回归测试。
- HAST 节点预算固定；语义 wiki 表格超过节点预算时，会省略行末由库生成的空补位格并记录警告，HTML 表格不受此规则影响。该降级不改变 schema，仍是同一主版本内可恢复的渲染快照。
- 1.x 接受同一主版本、适用 schema 相同、由库正常产出且来自可信边界的官方快照；不承诺恢复其他主版本、未知 schema 或第三方自造快照。
- 渲染快照是可重建的缓存：渲染快照失效而 AST 仍受支持时重新准备；AST 也不受支持时，用保留的原始源码、`pageName` 与解析配置重新解析。
- 缓存键应包含包版本、schema、parser/config、源码、`pageName`，以及 policy、labels、resolver、插件与模板数据版本；函数本身不能直接写进缓存键。
- 自定义语义节点与插件私有数据的格式由宿主管理，库不提供迁移保证。

  0.x 阶段还没有跨次版本的兼容基线：快照恢复、明确拒绝与重建规则以本节描述为准。

## 样式与安全基线

- 样式在 `react-wikitext/styles.css`，需要显式引入；库不设置全局元素样式。
- 内联样式只保留白名单内的排版与外观声明，`url()`、`expression()`、`!important` 等值整条丢弃并产生诊断；不依赖 `eval`，严格 CSP 下如需这些声明生效，按需放行 `style-src`。
- 不使用 `dangerouslySetInnerHTML`；最终 HAST 由清洗器与 wiki 策略生成。
- 图片默认不加载；只有解析回调授权的地址（或显式开启的插件图片策略）才会成为 `<img>`。
- React 入口只能在客户端组件中运行；根入口、`/view` 与 `/devtools` 的产物顶部已带 `"use client"` 指令，宿主侧不需要重复标记。

完整边界见[安全模型](../guide/security.mdx)与[渲染行为](../guide/rendering.mdx)。

## 验证兼容性

升级本库、React 或打包配置后，请在你自己的应用中重新验证渲染与快照恢复；维护者的完整检查流程见仓库根目录的 [`CONTRIBUTING.md`](https://github.com/BearBin1215/react-wikitext/blob/main/CONTRIBUTING.md)。
